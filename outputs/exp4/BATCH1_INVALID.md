# ⛔ 第一批（batch 1）——「只讀候選」的兩個 run 作廢，本檔只供存證

**這一頁的數字不得引用為結果。** run 2 與 run 4 讀到了對方寫的候選特徵。

## 為什麼作廢

run 2（只讀候選、reverse）與 run 4（只讀候選、forward）共用 `--tag cand_m128_r256`，
而 `scripts/run_exp2.py` 由 tag 推導側倉路徑，於是兩個 run 寫進同一個目錄。側倉檔名
是 `(tau, sample_key)` 的純函數，但**候選集合取決於快照當下的模型狀態** —— 兩個順序
的模型狀態不同，因此互相覆寫。

證據（mtime，epoch 秒）：

| task | 側倉 mtime | 寫入者 | 之後仍在讀它的 run |
|---|---|---|---|
| tcga_rcc | 1789661805–860 | run 4 | run 2（跑到 1789661915） |
| tcga_lung | 1789661825–898 | run 2 | run 4（跑到 1789661952） |

側倉檔數 2,273 = 各 task train 張數總和（120+616+763+774），證實共用同一組檔名。
兩個 run 都在自己的 stage 3 讀到了對方寫的候選特徵。

**run 1／run 3（讀整張）不受影響** —— 它們從不碰側倉。

修法見 commit `2cfc413` 與 `docs/ledger/DR-056.md` 的 2026-09-18 補記：側倉改為
一 run 一目錄，並在側倉檔加存 `cand_idx` 當身分憑據，載入時對不上即硬失敗。

## 作廢的數字（僅供對照，不得引用）

| 順序 | 設定 | ACC（class-IL） | Masked ACC（task-IL） | Forgetting ↓ | wall-clock |
|---|---|---|---|---|---|
| reverse | 讀整張（**有效**） | 0.7651 | 0.9124 | 0.1902 | 3,735 s = 62.2 min |
| reverse | 只讀候選（⛔ 作廢） | 0.7435 | 0.8898 | 0.2083 | 1,651 s = 27.5 min |
| forward | 讀整張（**有效**） | 0.8075 | 0.9071 | 0.0728 | 3,996 s = 66.6 min |
| forward | 只讀候選（⛔ 作廢） | 0.7831 | 0.8857 | 0.1241 | 1,545 s = 25.8 min |

作廢的配對差值：reverse ΔACC −2.16 pp、forward ΔACC −2.45 pp。
**這個方向不可解讀為方法的性質** —— 讀到別人的候選特徵本來就會變差。
有效的結論以第二批（`cand_m128_*_b2`、`DR056_PROBE.md`）為準。

## 另一件同批發生、但性質不同的事

第一批第一次啟動時，run 3／run 4 的順序旗標誤寫為 `--order forward`，但本 codebase
的正向順序叫 `main`（`run_exp2.py` 的 `ORDERS`），兩個 run 在參數分派就 KeyError、
未進入任何運算，隨即以正確旗標重啟。紀錄留在 `logs/exp4/failed_order_typo/`。
那是啟動器打錯字，不是程式缺陷，也與上面的側倉覆寫無關。
