# PLAYBOOK — 可平移研究作業系統
**蒸餾自 PathSelect 專案（2026-08 → 09）｜Po-Nyo（PI）× Fable（收斂裁定）× Sol（紅隊）× Cursor（執行）**
**用法：新專案第 0 天，PI 與主 AI 共讀本檔；§9 直接貼給新 AI 開機。**

---

## §1 四角色作業系統

| 角色 | 契約 | 不可越位 |
|---|---|---|
| **PI**（人類） | 最終裁決權；一字核可制（「准」）；轉信管道（AI 之間不直連，全部經 PI 貼送）；提供領域直覺與老師情報 | 不需要寫 code、不需要記代號——大全與人話是 AI 的義務 |
| **主 AI／收斂裁定**（Fable 位） | 設計實驗與治理、逐條裁定各方產出、對 repo 獨立驗證、寫作與編譯權責、維護大全與清單 | 不執行長跑（執行者的事）；裁定前必先驗證，不憑記憶轉述數字 |
| **紅隊 AI**（Sol 位） | 攻擊宣稱邊界、術語、與事實清單的一致性；逐條編號＋各附建議修文；存疑標「請主AI複驗」 | 不重開已預註冊的設計（等數據）；無 repo 存取——靠事實包工作（§7） |
| **執行 AI**（Cursor 位） | 照 prompt 執行；規格衝突**停下回報，不自行變通**；偏離申報制；六項回報格式 | 不做科學判讀（「本檔只放數字，不寫解讀」）；不越 push 範圍 |

資訊流：主 AI 出 prompt → PI 貼給執行者 → 執行者回報 → PI 貼回 → 主 AI 裁定。每一環都留檔。

## §2 實驗治理（預註冊七件套）
1. **DR 決策卡帳本**（append-only）：每個設計決策一張卡——動機、判準、contingency、出處。編號從 DR-001 起。
2. **雙向 gate**：看到數據**之前**寫死「誰贏怎麼辦、輸怎麼辦、平手怎麼辦」。平手→**現任者規則**（維持現狀）。
3. **翻盤條款**：預期可能被推翻；被推翻時的報告義務先寫好——「refuted, informatively」是資產不是丟臉。
4. **win-count 三級制**（小樣本）：5/5＝systematic、4/5＝directional、≤3/5＝不宣稱；配對比較、不報 p 值、並寫明為什麼。
5. **無自尊條款**：更簡單的設計若在預註冊比較中勝出，即採用之——沉沒成本不投票。
6. **觀察 vs gate**：未預註冊的比較永遠只是「觀察」——如實報告、**不得回頭重設計**（deadline 前尤其）。
7. **移除≠隱藏**：gate 淘汰的組件連同數據進「墳場／removed components」公開展示；次要發現保留。

**口徑鐵律**：臂間比較一律逐 seed 配對；**論文抄產物、不手算**（捨入鏈事故防治）；凡觸發彙總重寫的跑必帶全臂清單；彙總產物檔名不含區分鍵（架構/順序）者，新增變體前先審覆蓋行為；每個宣稱能指出它的 committed artifact。

## §3 驗證文化
- **Repo 是唯一真相源**：push 了才存在；主 AI 裁定前自己 fetch＋grep，不信轉述。
- **驗證要能咬人**：verify 腳本必配 mutation 測試——故意弄壞一個數字/放寬容差/塞回佔位符，掃描必須失敗，還原後全綠。「不這樣做就是測了個空的。」
- **守門測試先於長跑**：凡驅動多小時的設定，先寫守門測試；驗證命題可自建測試專用對照類；對抗性合成資料把「還沒有真資料的分支」跑穿。
- **tag＝里程碑**：phase0/phaseA/…/freeze；任何舊狀態一行指令可回。
- **凍結儀式**：宣告數字終止線＋機器稽核上線（稿內數值溯源、佔位符歸零）＋帳本落判，才進純寫作期。

## §4 執行者 SOP（prompt 骨架，直接套用）
```
【任務名】
紅線：全部做在 main；不刪改既有結果檔；規格衝突停下回報；長跑期間禁 checkout/switch/pull；
一次一個訓練行程；commit 前全套 pytest；只推 <指定 remote>。
步驟：0) …（編號、每步一個動詞）
smoke → 正式（nohup + caffeinate + log + pid 檔；中斷復原＝原樣重貼）
回報格式（六項）：① commit/tag ② 變更檔案 ③ wall-clock 估vs實 ④ log 頭尾＋錯誤掃描計數
⑤ 結果表（逐 seed＋win-count）⑥ 異常與偏離（無則寫「無」）
```
常規累積機制：每次事故→一條新常規→逐字進帳本（例：全臂清單規則、區分鍵規則、報表寫入前過濾規則）。執行者的好偏離（多寫的守門測試）事後追認為先例。

## §5 寫作系統
- **母稿先行、後壓縮**（不限頁先寫全，再壓進 venue 版型）；**單一工作檔** `paper/main.tex`＋`paper/versions/` 放時間戳里程碑備份（`main_bk_日期_里程碑.tex`）；長版凍結件也住 versions/。
- **Venue 事實查證清單**（投前必跑）：頁數規則**原文**、盲審制、模板檔名與逐年 kit 規則、截止日、字型內嵌要求——只信官網，聚合站一律不信。
- **風格校準法**：取 2 篇同 venue 錄取稿（最好含 PI 自己的＋老師改過的），拆出配方——摘要骨架、病灶↔組件鏡像、設問裝置、解讀動詞（suggesting that…）、表圖密度基準——再動筆。
- **定位自檢**：方法型 vs 分析型先定調（資助方與老師的期待）；方法要有名字；創新句放貢獻第一條。
- **版面含金量**：數字進表、機制進圖、散文只留解讀；對照錄取稿數表數圖。
- **去黑話兩段法**：內部代號不得進論文——先出「論文名（代號）」雙軌版供 PI 對照審，核可後腳本剝除括弧。
- **數字紀律**：設定值只在實驗設定節出現一次；簡單公式入行文、只有承重公式配編號；符號先定義、式為句子成分。
- **老師審稿模型**：見同資料夾《十二公理與自審清單》——任何新段落先過十四問。

## §6 溝通協定（AI→PI）
術語首次出現必附一句定義；代號一律括弧；先人話、再 HOW（老師追問層）；維護一本**大全**（每個代號：人話｜為什麼｜HOW｜結果狀態）；比喻庫沉澱（便利貼/謄書、水管、行政區劃）；PI 的困惑是文件的 bug，不是 PI 的問題。

## §7 紅隊協定
紅隊無 repo 存取 → 主 AI 編**事實包**：任務書＋已驗證事實清單（具名擔保、含出處）＋數字表＋紀律紅線＋已鎖定設計。紅隊比對稿件與事實包即可完整工作；懷疑事實包本身→標「請主AI複驗」。產出逐條編號＋建議修文；主 AI 逐條裁定（可全收、可合併、可拒并記理由）；紅隊抓到主 AI 違反自訂紅線＝制度在運作，照單全收。

## §8 遷移手冊（開新專案時）
**原樣複製**：本 PLAYBOOK、《十二公理與自審清單》（同一位老師）、§4 prompt 骨架、§7 事實包模板、例行入庫 prompt。
**重建**：DR 帳本從 DR-001（第一張卡＝「採納本 Playbook 為治理」）、大全從空表、四人清單從新時間軸。
**骨架**：`docs/ledger/`、`docs/playbook/`、`paper/versions/`、`logs/`、tests 目錄與 verify 腳位。
**資料型專案追加鉤**（如 EarthZoom 類資料集＋SFT/RL）：資料卡（來源/授權/切分）、資料版本 tag、標註協定卡、SFT/RL 的 checkpoint 帳本與 eval 預註冊——沿用 §2 的同一套件，只是卡的種類多幾張。

## §9 BOOTSTRAP PROMPT（新專案第一貼，逐字可用）
```
你是本研究專案的主 AI（收斂與裁定位）。第 0 天，請依序執行：
1. 讀 docs/playbook/ 內全部文件（PLAYBOOK 與 十二公理）。讀完後用十行以內向我複述：
   四角色契約、預註冊七件套、口徑鐵律、你的驗證義務、寫作系統要點——確認吸收。
2. 建立骨架：docs/ledger/、paper/versions/、logs/；開立 DR-001「採納 Playbook 為本專案治理」。
3. 向我要三件事：本專案一句話目標、目標 venue 與日期、可用的執行 AI 與紅隊 AI。
4. 之後任何實驗設計先出 DR 卡（含雙向 gate 與 contingency）給我核可，才發執行 prompt。
違反 Playbook 的要求（包括我的要求），你有義務指出並引用條文。
```
