# DR-032  長 job 必須有存活訊號；批次腳本不得用變數當命令
date: 2026-08-23    status: ACTIVE
context:   四段式 pipeline 在第一行就死，四段一段都沒跑。log 只有一行錯誤、
           沒有任何完成或失敗標記，是 PI 手動看 log 才發現。
           **直接原因是 zsh 不對未加引號的變數做 word splitting**：
           `R="python scripts/run_exp2.py"; $R` 被當成單一檔名（bash 則會展開）。
           腳本的 cd 有生效，不是相對路徑問題。
options:   (a) 只修這次的腳本 (b) 立規則：存活訊號 + 禁止變數當命令
ruling:    (b)。憲法 §3.7：每完成一階段在 log 追加
           `[heartbeat] <ISO時間> stage=<n/N> <描述>`；非零結束時追加
           `[FAILED] <階段> <錯誤摘要>` 並寫 outputs/_status/<job>.json
           記錄 {state, stage, note, updated_at, started_at}。
           附帶條款：批次腳本不得用變數當命令，每行都要是完整可執行的命令。
           腳本一律寫進 repo（scripts/），不放暫存目錄；開頭 cd 絕對路徑；
           啟動前 zsh -n 語法檢查 + 第一段最小規模實跑。
evidence:  outputs/exp2/pipeline.log（第一行即失敗）；scripts/job_status.py；
           scripts/pipeline_20260823.sh；驗證方式：以會失敗的迷你腳本實測
           [FAILED] 與狀態檔確實產生
