# DR-057  M = 64 備份實驗（5090 pod，exp5）
date: 2026-09-23    status: ACTIVE
context:   ICASSP 2027 投稿改用 replay memory |M| = 64 張 WSI。主要數據由同學在 H200
           上跑；本批是**備份**。PI 指示：若 H200 在 **9/23（三）16:00 台灣時間**前
           沒有完整結果，整篇論文改用本批數字。**兩套數字絕不混用。**

           盤點（`docs/M64_NUMBER_INVENTORY.md`，先於本卡完成）查出一件會擴大範圍的
           事實：`run_exp2.py:247` 取樣記憶體的條件是 `kd` **或** `eq` **或** `replay`，
           所以 **B1（只有 KD）與 B2（只有 hinge）也依賴 |M|**，即使其 `replay=False`。
           指示中的「含 replay 的設定」會低估影響範圍；本卡依程式碼為準。

           另查出 |M| = 512 在 reverse 的第一個任務其實**沒有綁住**（esca 只有 120 張），
           而 |M| = 64 在兩個順序都從第一個任務起就綁住，且每個 stage 的任務組成都會變。
           因此這不是二階效應。
options:   (a) 只重跑 Table 1 那一列
           (b) 重跑所有依賴 |M| 的數字（Table 1、Table 2、Table 3、buffer sweep）
           (c) 同 (b) 再加 B sweep
ruling:    **(b)，並在時間允許時延伸到 (c)。** 佇列嚴格照優先序，跑不完就從尾端截斷。

           ## 使用規則（凍結，不因數字高低改變）

           * H200 那套若在 **9/23 16:00（台灣時間）**前完整完成 → 論文全部使用 H200 數字，
             本批不用。
           * 否則 → 論文**整套**改用本批數字。
           * 兩套都完成時**不比較數字高低**，依上述規則選。
           * **絕不混用**：不得一張表用 H200、另一張用本批，也不得在同一張表內混列。
           * 本批所有 run 都在同一台 5090 pod 上完成。**不得與 exp3、exp4、H200 的輸出
             相減或補位**（跨機器浮點分歧可達 2.8 pp，與真實效應同量級，見 DR-052）。

           ## run 清單與優先順序（預註冊）

           共同設定與 Table 1 的 protocol 完全相同，只改 `--mem-capacity`、`--arms`、
           `--budget`：`--head accumulating`、`--uold current`（含 hinge 的臂）、
           `--arch hier` 或 `flat`、十折、`seed = fold`。

           | 優先 | 內容 | run 數 |
           |---|---|---|
           | P0a | 協定核對：A5 hier、`--uold current`、**M=512**、fold 1、reverse | 1 |
           | P0b | Table 1：A5 hier、M=64、reverse ＋ forward | 20 |
           | P0c | Table 2 其餘可變列：A3（M=64，兩序）＋ A5 flat ucur（M=64，兩序） | 40 |
           | P1 | buffer sweep：M ∈ {16, 32, 128, 256, 512}，A5 hier，**reverse** | 50 |
           | P2 | Table 3：B1／A3／A4（snapshot）＋ B2／A5（ucur），fold 1、seeds 0–4、flat、reverse | 25 |
           | P3 | B sweep：B ∈ {4, 16}，M=64，A5 hier，兩序（僅在 P0–P2 於 9/23 12:00 前完成才跑） | 40 |

           **合計 P0–P2 = 136 run；加 P3 = 176 run。**

           ⚠️ **對指示的一處偏離，理由如下。** 指示的 P2 寫「Table 3 … 兩序 → 每項 20 run」
           （十折兩序）。但 Table 3 的協定是 **fold 1、5 seeds、flat、reverse**
           （main.tex:230）。以十折兩序重跑會得到**不屬於 Table 3 的數字**，放進去會讓
           表格與它自己的 caption 不符。因此 P2 依 Table 3 自己的協定重跑（每臂 5 run，
           共 25 run），而不是每項 20 run。這同時更省機器時間。

           不跑的部分與理由：
           * **A1**（Table 2 第 1 列）、**A2**（Table 3 第 1 列）記憶體從不填也不取，
             對 |M| 完全免疫 → 直接沿用既有數字。
           * **ZS-top8**（Table 2 第 5 列）零參數、與 stage 無關 → 沿用。
           * **M = 0**：`SelectionMemory.__init__` 對 `capacity <= 0` 直接 raise
             （`selector/memory.py:127-128`），程式不支援。依規則「必須改程式才能跑就跳過」，
             不跑；在報告中說明並討論能否以 Table 2 的無保護列代表 M=0
             （**不等價**：A1 連 LoRA 都沒有，A2 有 LoRA 但無保存，兩者都不是
             「有完整保存機制但記憶體為空」）。
