### B4　指標（`sota/metrics.py`）

| 指標 | 來源 | 可信度 |
|---|---|---|
| ACC | 官方 `manager/manager.py`：`average_test_acc = sum_test_acc / len(dataset_names)` | **核對過** |
| Masked ACC | 官方 `_eval_masked_metrics`：`y_hat[:, label_shift : label_shift + subtype_num]` | **核對過** |
| BWT | **Lopez-Paz & Ranzato (2017)**，GEM（PI 裁定，Prompt 6-3） | 依原始文獻 |
| Forgetting | **Chaudhry et al. (2018)**，Riemannian Walk，**max-based**（PI 裁定，Prompt 6-3） | 依原始文獻 |

    BWT        = mean_{j<T−1} ( A[T−1][j] − A[j][j] )              ← 基準點＝對角線
    Forgetting = mean_{j<T−1} ( max_{l∈[j,T−2]} A[l][j] − A[T−1][j] )  ← 基準點＝峰值

⚠️ 無法從基準論文逐行核對：它正文只引三篇而**沒有印公式**，
官方 repo 也只記錄 forgetting 的**過程**、沒算純量。故依原始文獻，出處由 PI 裁定。

**一致性佐證**：從其論文表抽出 **28 組 (Forgetting, BWT)**，
**每一組都滿足 `Forgetting ≥ |BWT|`，零反例**；多數恰好相等，
少數明顯分離（最極端 ConSlide 的 0.058 vs −0.021）。這正是上面兩式的指紋 ——
基準點不同故恆有 `Forgetting ≥ −BWT`，並在「學完任務 j 之後準確率還會再上升」
時分離，同時**否證**了「Forgetting 直接定義為 −BWT」的簡化讀法。

我們的真實資料**確實落在兩式分離的區間**（A5 seed0：task 0 的峰值在 stage 1 的
0.8667 而非 stage 0 的 0.8000 → Forgetting 0.0762 ≠ −BWT 0.0452），
所以兩個欄位不是重複的。`tests/test_sota_metrics.py` 把這件事釘成測試。

### B6　OPCM-Merge (adapted)

出處：Bui et al., *MergeSlide*, arXiv:2511.13099（WACV 2026），Eq. (3)–(5)；
官方實作 `caodoanh2001/MergeSlide::opcm_mergeslide.py`。
**重新實作，未移植任何一行程式碼。**

**⚠️ 發現一：官方程式的零對角遮罩是 no-op。**
它寫 `projected_task_tv.diag().fill_(0)`，但 `Tensor.diag()` 對 2-D 輸入回傳
**副本**（torch 2.11 實測），不是 view —— 那一行沒有改到被投影的矩陣。
少了遮罩，full SVD 下 `U (Uᵀ Δθ_t V) Vᵀ ≡ Δθ_t`（實測誤差 9e-7），
`G(·)` 退化成恆等，`merge_linear_weights` 與 `merge_other_parameters` 完全相同。

⚠️ **修正先前的簡化說法（2026-09-05）**：本卡原本寫「官方跑出來的是『直接相加』」，
**只對了一半**。遮罩失效讓 `G(·)` 變恆等，但 **λ 正規化仍在做事** ——
官方行為是「直接相加**再整體縮放**到『至今各任務 task vector 範數的平均』」。
張量層實測（seed 0，最終階段）：

| | ‖Δθ̃‖ | 與 C1(sum) 的 cos |
|---|---|---|
| C1（直接相加，無縮放） | 3.3304 | 1 |
| OPCM-nomask（官方行為） | **1.4893** | **1.0000025** |
| OPCM（論文 Alg. 1） | **1.4893** | 0.998352 |

`OPCM-nomask` 與 `C1` 縮放對齊後**最大逐元素差 3.9e-08** —— 兩者確實只差一個純量。
而兩版 OPCM 的**範數完全相同**（λ 把它們都拉到同一個目標範數），
**只差方向** —— 這是對「遮罩到底做了什麼」很乾淨的隔離。
本檔照**論文**實作（用 `.diagonal()`，實測 ⟨G, Δθ̃⟩_F ≈ 0 成立），
並提供 `--no-mask` 重現官方行為。兩者 `tests/test_sota_opcm.py` 都釘住。

**⚠️ 發現二：λ 的分母，論文寫 `‖θ_i‖₂`，官方程式用 `‖θ_i − θ_base‖₂`**
（`get_task_vector_norm`）。本檔照**程式** —— `‖θ_i‖₂` 含未微調的基礎模型本身、
量級由 θ_base 主導，會讓 λ 幾乎不隨任務變化，顯然不是原意。
λ 是**全域純量**（整份 state dict 攤平後取範數），不是逐矩陣算，同樣照程式。

**接法**：θ_base = θ₀，θ_t = θ₀ + Δ_t，Δ_t 直接取自 C1／C2 已算好的
`outputs/exp2/main/dr046_deltas_seed{seed}.pt`（每任務各自從同一個 θ₀ bare 訓練），
正是 OPCM 假設的輸入。⚠️ 因此 OPCM 只在 **fold 1、seed 0–4（DR-046 協定）** 存在，
不是 SOTA 主表的 10 折 —— `docs/SOTA_TABLE.md` 逐列標明。

### B6　zero-shot 參照線
`meanpool`（全部 patch 等權）與 `rand8`（隨機 B 個，與主線同預算），共用凍結的
CONCH 頭，**沒有可訓練參數** → 跨 stage 完全不變，Forgetting 與 BWT 必然為 0。
這不是「不遺忘的好方法」而是「沒有東西可遺忘」，表中標成參照線而非 CL 方法。
冒煙實測 Forgetting = 0.000，符合預期。

**`meanpool` 的記錄不帶 `B` / `selected_idx` / `weights_*`（2026-09-04 修正）。**
第一版照抄選取類的欄位寫，被 `tests/test_per_slide_records.py` 抓到兩個問題：

1. **權重歸不了一**：`round(1/n, 6)` 在 n 幾千時累積誤差達 **1.7e-3**
   （n=4808 → 0.000208 × 4808 = 1.001728），超過測試的 1e-3 容差。
2. **量體**：`selected_idx` 就是 `range(n)`（n 最大 8466）、權重是 n 份相同的數，
   **單折 57 MB**，十折 570 MB 全是冗餘。

處置不是放寬測試，而是**改正分類**：meanpool 沒有預算、也沒有做選取，
本來就不該算「選取類評估」。`test_per_slide_records._is_selection_dump` 正是
以 `B` 欄位的有無判定，並註明沒有 patch 選取這回事的只需滿足 REQUIRED ——
拿掉 `B` 是照它既有的語意走，不是繞過它。改帶顯式的 `pooling` 欄位
（`"all"` / `"random"`），`n_patch` + `pooling` 已完整說明發生什麼事。
產物 **57 MB → 279 KB**。

⚠️ **突變檢查**：把 `B` 與那些欄位加回去（＝修正前那一版），
`test_per_slide_records` 立刻失敗（`softmax 權重未歸一`）——
確認守門仍然有效，不是被繞過。

### 配對統計的報告慣例
逐折同折相減，**只報 k/10 的折數與均值差，不貼三級標籤**。

理由（寫進報表本文）：**DR-020 的三級規則是為 5 個 model seed 校準的**，
這裡的變異源是**資料切分**，沒有重新校準過，套用會是誤用。
這與本卡 ruling 早先寫的「無勝負門檻（不套 DR-020 的三級規則）」一致。

「較佳折數」**帶方向**：ACC / Masked ACC 越大越佳、Forgetting 越小越佳 ——
三軸都以「A 較佳」計數，不是一律數正號（這是最容易寫錯的一條，
`test_paired_counts_forgetting_the_other_way_round` 專門守它）。
