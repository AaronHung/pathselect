           **三項需要 PI 注意的發現：**

           1. **flat 架構下 F_g 在 task 1 收不到任何 task-relevant 梯度。**
              `a_soft`（= softmax(r) 的 STE 注入）雖在 flat 下仍被計算，
              但只在 `for j in (range(...) if hierarchy else ())` 迴圈內被使用 ——
              該迴圈在 flat 下不執行。因此 flat 的 F_g 只從 `L_KD` 的 group 項
              收梯度，而 task 1 記憶體為空、不進 `continual_terms`。
              這與 `selector/rounds.py` L36–48 記載的設計意圖一致
              （flat 本就不用 group 配額），但**「F_g 有在學」這句話在 flat 列
              不成立**，論文若有相關陳述須逐句核對。

           2. **Table 3 的 ΔU 是「逐 slide 加總後對舊 task 平均」。**
              改為逐 slide 平均後，−220.4／−300.8／−16.8 變成
              **−3.796／−4.705／−0.743**。相對關係不變，但絕對量級差約 60–70 倍，
              因為各 task 的 test 片數不同（15／76／93），加總口徑讓片數多的
              task 主導。**單位在稿內須寫清楚**，否則讀者無從判斷量級。

           3. **hinge 只在 1.7%–7.4% 的 replay 步驟啟動**（stage 1/2/3 分別
              0.0169／0.0305／0.0740，A5 flat fold 1 五 seed 平均）。
              資料早已記錄於 per_slide 的 `l_eq_fire_rate`，不需重跑。
              這對「L_eq 貢獻多少」的敘述是直接相關的量化背景。

           另修正一處先前的粗略說法：replay 與 hinge 確實在**同一步、同一張
           重放 slide** 上計算，但兩者的梯度**不相同** —— replay 走 softmax 加權
           池化、hinge 走等權池化（`weighting="uniform"`）。方向高度相關，
           但不是同一個 dCE/dθ。
