# DR-026  執行期檔案凍結；長 job 必須檢查 exit code
date: 2026-08-25    status: ACTIVE
context:   編輯 run_exp2.py 時排隊中的 job 正要呼叫它，抓到改到一半的版本
           （NameError: ALLOCATION_MODES）。G1' 因此整批被靜默跳過 —— shell 沒檢查
           exit code，run_exp2 crash 後仍印出「完成」。671 條測試當時全綠，
           因為 import 模組不會執行 main()，argparse 內的 NameError 無人攔截。
options:   (a) 只修這次的檔案 (b) 立規則 + 補上能抓到這類失敗的守門
ruling:    (b)。憲法 §3.4 執行期檔案凍結：有 job 在跑時不得編輯它會呼叫的檔案；
           必要時複製到 scripts/_frozen/ 讓 job 呼叫凍結副本。長 job 啟動與結束
           各記一次所呼叫檔案的 commit hash，不同即標「執行期檔案曾變動」。
           §3.5 長 job 的 shell 一律 set -e。
           新增 tests/test_cli_entrypoints.py：每個 CLI 腳本的 `--help` 必須跑得起來
           （走完 argparse 設定），這是 import 測試抓不到的一層。
           ⚠️ 這次因語法錯誤而大聲失敗；若編輯語法正確但語意不同，排隊 job 會
           **靜默地用新行為跑出結果**，那才是真正危險的情境。
evidence:  outputs/exp2/h_series.log、outputs/exp2/g1prime.log（兩次 NameError）；
           tests/test_cli_entrypoints.py（mutation check：拿掉 import 即被抓到）
