# DR-028  報告腳本必須有最小資料煙霧測試
date: 2026-08-24    status: ACTIVE
context:   report_hier2.py 因 NameError: diag 而在 G1' 批次末尾 crash —— diag 是在
           report_hier.py 的診斷區塊定義的，複製時只帶了用法沒帶定義。
           同類錯誤三次：8/23 ALLOCATION_MODES（--help 抓得到）、同日 diag
           （需真實資料才觸發，--help 抓不到）、以及更早的替換未命中。
           追查時另發現：report_hier.py 的結構性診斷區塊**從未真正寫進腳本**，
           HIER.md 一直沒有那一節，但我在回報中貼出過該表。
options:   (a) 只修 diag (b) 加一層「用真實資料跑完 main()」的測試
ruling:    (b)。憲法 §3.6：每個報告腳本必須有一條測試，用最小的真實或 fixture 資料
           實際跑完 main()，斷言產出非空且含預期章節標題；批次腳本在宣告完成前
           必須先成功執行其報告腳本。已補回 report_hier.py 與 report_hier2.py 的
           結構性診斷區塊並重新產出兩份報告（此次以 §2.7 的錨點斷言方式套用）。
evidence:  tests/test_report_scripts.py（mutation check：拿掉 diag 定義、
           拿掉結構性把關段落，兩者皆被抓到）；outputs/exp2/hier2/HIER2.md
