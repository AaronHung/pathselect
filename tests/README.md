# 測試開發準則

## 1. 新增的斷言必須先被證偽過（mutation check）

**每一條新增的 assert，在提交之前必須以人工製造的違例驗證它真的會失敗，再還原。**

```
1. 寫好斷言
2. 手動破壞它應該保護的東西（刪一列、改一個值、拿掉一個欄位…）
3. 跑測試，確認它 FAIL 且錯誤訊息指得出問題在哪
4. 還原
5. 再跑一次，確認 PASS
```

**永遠為真的斷言是裝飾品，而且比沒有測試更糟 —— 它會給人虛假的安全感。**

實例（`tests/test_ledger.py::test_dr_numbers_have_no_gaps`）：寫完之後把
`INDEX.md` 的 DR-018 那一列移除，確認測試失敗並在訊息中指出
`DR 編號有缺口：['DR-018']`，然後還原。若當時沒做這步，就不會知道
INDEX 的表格解析正則是否真的抓得到那一列。

### 提交訊息要求

提交訊息中以**一行**註明已做過 mutation check 與製造的違例為何：

```
mutation check: 移除 INDEX 的 DR-018 那列 → test_dr_numbers_have_no_gaps FAIL，已還原
```

該次提交沒有新增斷言時，寫 `mutation check: 本次未新增斷言`。

### 範圍

- **只對 2026-08-24 之後新增的斷言要求。** 既有的測試不回頭補。
- **不建自動化 mutation testing 框架。** 時程不允許；人工驗證 + 提交註記就夠。
  這是一條紀律，不是一個工具。

## 1b. 科學主張也要 mutation check

同一條紀律延伸到**論文會寫出去的主張**，不只是測試：

> **當要宣稱「某模組有作用 / 無作用」時，優先用替換或擾動實測，不要只讀 code 推論。**

實例（G0，2026-08-24）：要判斷 flat 模式下 Group Selector 對選取有沒有影響，
不是讀 `run_rounds` 的分支就下結論，而是**把整個 F_g 換成權重放大 5 倍再加噪的
另一個網路**，確認選出的 patch 集合位元相同 —— 這才把「零影響」從推論變成證據。
反向對照（同樣的替換在 hier 下會改變選取）同樣必須做，否則無法排除「替換本身
無效」這個平庸解釋。

兩條常見的自欺：
- 只讀 code 推論「這條路沒被走到」，但實際上被走到了、只是效果小。
- 只做正向替換不做反向對照，於是分不清「模組沒作用」與「替換沒生效」。

### 陷阱：數值不可分辨的違例

mutation 必須真的改變被斷言的性質。`0.0 * kl + patch` 與 `patch` 在浮點上完全
相等，所以「把提前 return 拿掉、改成乘以零」這個違例**不會**被數值斷言抓到 ——
差別只存在於計算圖（前者讓 `.grad` 是全零張量，後者保持 `None`）。
遇到 mutation 沒被抓到時，先問是**測試太弱**還是**違例太弱**，兩者都要修。

## 1c. 文件數字的溯源檢查（`scripts/verify_doc_numbers.py`）

治理文件（CLAIMS / DR 卡 / PROJECT_NARRATIVE / RESULTS_DOSSIER）裡的每個數字都要能
從產物溯源。三層：

- **Tier 1**：從 `per_slide/*.json` **重算**配對統計，再比對文件的錨定段落 —— 完全不經過任何 `.md`
- **Tier 1b**：同上，但對照組可指定（`hier2 A5 − hier2 A3`、`hier2 A5 − hier2 A5nG`）
- **Tier 2**：文件寫的數字必須**同時**出現在被引用的產物裡

### 2026-08-26 的 mutation 結果：56/56 全數抓到

把每個登記數字改一位 → 檢查必須 fail。全部 56 項（Tier 1 八項、Tier 1b 四項、
Tier 2 四十四項）逐一驗證通過。

**過程中被 mutation 打掉的三個假通過**，都值得記住：

1. **整份文件的子字串搜尋**：`5.92` 在別處出現就算通過。→ 改為行/段落級錨定。
2. **`(not in_doc) or in_art`**：文件把數字改錯後 `not in_doc` 為真，**空洞地通過**。
   → 改為「文件與產物都必須有」。
3. **四捨五入容忍**（最陰險）：為了讓總表寫 `−0.50`、產物寫 `-0.497` 也能過，
   允許「少一位小數」的寫法。結果 `+0.31` 命中了 `+0.317`（前綴），
   而 `-0.005` 的 2 位形式 `-0.01` 命中了文件裡**另一個不相干的數字**。
   38 條裡有 31 條漏抓。→ **模糊比對在治理文件上不可用**：
   數字必須以完整數字出現（左右不接數字），總表刻意寫縮寫時在
   `QUOTED` 第 5 欄**明列**文件端字串，而不是容忍。

**教訓**：一個「全部通過」的檢查器，在做過 mutation 之前不算證據。
這三個 bug 每一個都讓檢查器看起來在工作。

### 跑 mutation 迴圈的兩個操作教訓

- **先 commit 再跑**。mutation 會改動工作區的檔案；腳本被中途砍掉時 `finally`
  不一定跑得到（實際發生兩次），有 git 才能 `git checkout --` 復原。
- **不要用 subprocess 跑 N 次**。56 × 4 秒會超過工具逾時；直接 `import` 後呼叫
  `main()` 並用 `redirect_stdout` 吞掉輸出，整輪不到十秒。

## 2. 執行

```bash
python -m pytest tests/ -q
```

測試不需要 GPU。需要資料集或 CONCH checkpoint 的測試會在缺少時 `skip`，
不會失敗。
